LEDGER - GitHub edition
1. Create a public repository ledger-app. Upload index.html, sw.js, manifest.webmanifest and both PNG icons to its root. Settings > Pages > Deploy from a branch > main / root. Open the published HTTPS URL.
2. Create a separate PRIVATE repository ledger-data. Initialize it with a README so it has a default branch. Never publish this repository.
3. GitHub Settings > Developer settings > Personal access tokens > Fine-grained tokens > Generate new token. Select only ledger-data, grant Contents Read and write (Metadata read is automatic), set an expiration. Copy token. Do not commit it anywhere.
4. In Ledger enter owner/ledger-data, token, and a strong unique encryption password (12+ characters). Connect GitHub. Keep password and token in a password manager. Remember credentials is optional and stores them unencrypted in browser storage; use only on a trusted device. The local ledger and manual exports are also unencrypted.
5. On iPhone open the published URL in Safari > Share > Add to Home Screen. Open the installed app online once before going offline. On Windows open the same URL in Chrome or Edge. No Vercel needed.
6. Sync runs after changes, on reconnect, and every 30 seconds while open. One encrypted ledger-backup.json file is updated using GitHub's SHA check. GitHub retains commit history. No guaranteed background sync on iOS. Renew expired tokens. On a replacement device connect with the same repository and encryption password and a valid token. Do not lose the password.
7. Different record edits merge; simultaneous changes to the same record stop sync rather than overwrite. Export local JSON before manually resolving a conflict. Avoid simultaneous edits to the same record. Use one active tab per device. GitHub file size limits apply. Verify backup status before relying on recovery. Manual exports are plaintext.
8. Syntax checked only; live GitHub and iPhone testing not performed. Test with sample records before using real data.
